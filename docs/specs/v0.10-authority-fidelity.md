# HorusTrace v0.10 — Authority Fidelity

Status: implementation started  
Baseline: HorusTrace v0.9.0 / frozen 180-repository study  
Source study: Real-World Agent Security Study 2026

## Objective

v0.10 improves the correctness of effective Agent -> Tool / MCP authority relationships.

v0.9 made discovery substantially more complete. v0.10 answers the narrower question:

> Which discovered relationships are actually proven authority relationships, and what source evidence proves them?

The governing invariant is:

> entity existence != authority

A tool, workflow node, MCP server, or capability may be structurally visible without being
an effective-authority target of an agent.

## Relationship proof contract

An effective-authority relationship is emitted only when static evidence proves an
invocation/binding path.

Strong evidence includes:

- explicit tool membership in an agent constructor or framework factory;
- statically resolved tool collection supplied to an agent;
- explicit framework-native AgentTool / agent-as-tool binding;
- explicit MCP server/toolset collection supplied to an agent;
- model-visible tool catalogue plus model-selected concrete dispatch;
- graph tool execution where both the tool catalogue and route to the executor are
  statically resolved;
- explicit repository/deployment binding that is defined by the framework contract.

The following are insufficient by themselves:

- same file or module;
- same repository;
- name similarity;
- graph/workflow node registration;
- topology containment;
- discovery of an unbound tool or MCP server;
- a generic `tools=` keyword without model/agent semantics;
- proximity to an agent node.

When evidence is insufficient, preserve the entity/topology and report the relationship
as unresolved/unbound rather than manufacturing effective authority.

## Workstream 1 — remove topology-derived authority

The v0.9 LangGraph adapter deliberately retained legacy Tool projections for
`add_node(...)` registrations so finding behavior did not change during the Recall
Foundation release. Those projections are useful for capability/finding analysis but
workflow registration alone does not prove Agent -> Tool authority.

v0.10 marks these objects as workflow projections, preserves their topology/capability
visibility, stops emitting ADG `INVOKES` edges for them, and excludes them from
effective-authority relationships.

Frozen-baseline concentration motivating this first change:

- rw-047: 18 authority false positives;
- rw-051: 16;
- rw-052: 16.

These three LangGraph cases account for 50/78 precision-eligible authority false
positives and contain zero authority true positives in the locked reference.

## Validation discipline

Every authority semantic PR must:

- run against the same frozen 180 exact-SHA cohort;
- report authority TP/FP/FN and precision/recall deltas;
- report per-framework deltas;
- preserve v0.9 discovery gates;
- leave locked truth immutable;
- record genuine reference disagreements separately;
- avoid adding heuristic authority solely to recover recall.

Runtime effectiveness remains `not_verified`.
