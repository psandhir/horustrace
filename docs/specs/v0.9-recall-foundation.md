# HorusTrace v0.9 — Recall Foundation

Status: Implementation complete; closeout evidence recorded, release tag pending precision-adjudication review  
Target: v0.9.0  
Source study: Real-World Agent Security Study 2026  
Frozen baseline scanner: `418db4e29798a7d25df686dd7bccfd9fefa225bd`

Closeout: `docs/research/v0.9-recall-foundation-closeout.md`

## Objective

v0.9 improves cross-framework semantic discovery before HorusTrace expands its policy catalogue.

The 2026 real-world study showed that HorusTrace is conservative when it recognizes agent roots, but misses large parts of heterogeneous agent systems and binds effective authority too broadly in some workflows.

Baseline:

| Dimension | Precision | Recall |
| --- | ---: | ---: |
| Agent/workflow entities | 0.971 | 0.499 |
| Tools | 0.489 | 0.267 |
| MCP servers | 0.000 | 0.273 |
| Delegation edges | 0.944 | 0.776 |
| Effective authority | 0.278 | 0.611 |

Measured deficits:

- LangGraph accounts for 252/346 missed agent/workflow entities.
- LangGraph tool recall is 0.068.
- MCP/custom agent recall is 0.063.
- MCP/custom tool recall is 0.000 and accounts for 408/814 missed tools.
- 16/22 explicit MCP servers were missed.
- one unreadable filesystem path caused the only scanner execution failure.

The v0.9 principle is:

> discover correctly → preserve provenance → remain unresolved when evidence is insufficient.

## Release gates

v0.9 is validated against the unchanged frozen 180-case cohort and locked source reference.

| Metric | v0.8 baseline | v0.9 gate |
| --- | ---: | ---: |
| Overall agent precision | 0.971 | >= 0.95 |
| LangGraph agent recall | 0.250 | >= 0.80 |
| LangGraph tool recall | 0.068 | >= 0.70 |
| MCP/custom root recall | 0.063 | >= 0.60 |
| MCP/custom tool recall | 0.000 | >= 0.60 |
| Explicit MCP-server recall | 0.273 | >= 0.85 |
| Scanner execution success | 179/180 | 180/180 |

Additional invariants:

- delegation precision remains >= 0.90;
- dynamic constructs are never promoted to fully resolved without evidence;
- frozen baseline and truth artifacts are immutable;
- every semantic PR publishes a delta against the same cohort;
- no target repository is imported, installed, or executed.

## Workstream 0 — post-fix validation harness

Before scanner semantics change, add a repeatable way to run any candidate HorusTrace SHA against the frozen cohort.

The harness must:

- validate the frozen cohort and locked truth;
- accept an explicit candidate scanner SHA;
- execute the same 180 exact-SHA repositories;
- write results under `results/postfix/<scanner-sha>.json` and `.md`;
- compare candidate results with `results/frozen-baseline.json`;
- report overall and per-framework metric deltas;
- list execution regressions and metric regressions;
- never replace the immutable frozen baseline.

This becomes the mandatory validation mechanism for v0.9 semantic PRs.

## Architecture — semantic discovery before security inference

Current Python adapters normalize source directly into `horustrace.models.Graph`. That is appropriate when source maps cleanly to Agent → Tool, but it forces ambiguous workflow constructs into security entities too early.

v0.9 introduces an internal semantic-discovery representation used by selected adapters before projection into the public Graph model.

Suggested concepts:

```
SemanticEntity
  id
  name
  kind
  framework
  location
  provenance
  metadata

SemanticBinding
  source
  target
  kind
  basis
  resolution
  location
  metadata
```

Minimum entity kinds:

- agent
- workflow
- tool
- mcp_server
- control
- transform
- unknown

Minimum bindings:

- contains
- invokes
- advertises
- dispatches_to
- delegates_to
- binds_mcp
- routes_to

Resolution:

- proven
- partial
- unresolved

The v0.9 public Agent/Tool/MCPServer/ADG output remains backward compatible. A wholesale adapter contract migration is out of scope.

## Workstream 1 — LangGraph semantic adapter v2

Primary implementation: `src/horustrace/adapters/langgraph.py`.

### Graph recognition

Support:

- StateGraph and MessageGraph;
- aliases and statically resolvable builders;
- compile calls;
- graph-returning helpers;
- subgraphs;
- notebook-extracted Python source.

### Node-role classification

Every `.add_node(...)` registration is classified as one of:

- model_agent
- tool_node
- subgraph
- control
- deterministic_transform
- unknown

Evidence must drive classification.

A deterministic state-transform function is not an Agent merely because it is a graph node.

Model-agent evidence can include explicit agent factories, known agent executors, model invocation in the callable, or a constructed agent object registered as a node.

Tool-node evidence includes ToolNode and explicit tool-executor constructs.

Control evidence includes router functions, tools_condition, and callables returning graph targets.

Unknown nodes remain workflow nodes and contribute coverage diagnostics.

### Tool discovery

Support:

- LangChain `@tool`;
- StructuredTool;
- explicit tool sequences;
- variables holding tool sequences;
- ToolNode;
- create_react_agent tools;
- statically resolvable helper-generated lists;
- bound tool collections.

A tool attached to one graph/agent path must not be attached to every node in the module.

### Control edges

Normalize:

- add_edge;
- add_conditional_edges;
- START/END;
- route maps;
- statically resolvable returned targets;
- supervisor routing;
- subgraph entry/exit.

Dynamic routing remains unresolved unless the candidate set is explicitly complete.

### Factories

Cover:

- create_react_agent;
- create_supervisor;
- swarm constructs;
- graph-backed LangChain create_agent;
- agent-as-node patterns.

Acceptance gate: LangGraph agent recall >= 0.80 and tool recall >= 0.70 while precision remains >= 0.90.

## Workstream 2 — framework-neutral model/tool-loop discovery

Add `src/horustrace/adapters/model_tool_loop.py`.

Do not classify code as agentic simply because it calls an LLM.

A generic tool loop requires evidence linking model invocation, advertised tools, and model-selected dispatch.

Recognize statically resolvable patterns such as:

- dict/list registries of callables;
- provider function/tool schemas;
- OpenAI-compatible tool parameters;
- response.tool_calls style dispatch;
- dispatch maps and bounded if/elif routers;
- helper-class dispatch where the lookup path is provable.

False-positive controls must exclude:

- SDK/library code;
- MCP servers without a model loop;
- schema generators;
- deterministic command dispatchers;
- test fixtures;
- LLM calls with no model-controlled tools.

If only part of the chain is visible, emit coverage diagnostics instead of fabricating an agent/tool relationship.

Acceptance gate: MCP/custom root recall >= 0.60 and tool recall >= 0.60.

## Workstream 3 — MCP discovery and binding v2

Primary areas:

- adapters/mcp_python.py
- adapters/mcp_config.py
- mcp_context.py
- mcp_authority.py
- OpenAI/Pydantic/framework-neutral adapters

Recognize:

- ClientSession;
- stdio;
- SSE;
- streamable HTTP;
- remote URLs;
- commands and arguments;
- helper-returned sessions;
- statically resolvable MCP collections;
- list_tools / call_tool loops;
- framework-native MCP constructor collections;
- config-backed server declarations.

Environment-derived endpoints may retain symbolic provenance when their value cannot be resolved.

### Binding

Attach an MCP server directly to an agent only when source evidence supports the relationship.

Strong evidence includes:

- server passed to agent constructor;
- agent toolset membership;
- model receives server-derived tool catalogue;
- model-selected dispatch reaches that MCP session.

Module-level co-presence is insufficient.

Unproven servers remain unbound or unresolved.

Binding metadata must retain a basis such as:

- agent_constructor
- toolset_membership
- client_tool_catalogue
- model_dispatch
- config_reference
- framework_wrapper
- dynamic

Dynamic tool filters remain partial/unresolved rather than being treated as a known unrestricted catalogue.

Acceptance gate: explicit MCP-server recall >= 0.85.

## Workstream 4 — repository traversal hardening

Scanner traversal must recover from:

- PermissionError;
- broken symlinks;
- inaccessible directories;
- stat/read OSError;
- files disappearing during traversal.

Unreadable evidence produces a coverage diagnostic and scanning continues.

Suggested diagnostic:

- id: ARG-COV-019
- kind: unreadable_path

Diagnostic details should contain the repository-relative path, failed operation, and exception type.

Symlinks must not allow traversal outside the canonical scan root.

Acceptance gate: 180/180 frozen cases complete.

## Discovery observability

New semantic discoveries should preserve enough machine-readable evidence to answer:

- which adapter discovered this entity?
- which source construct created it?
- where is the source?
- why was it bound to this agent?
- is that relationship proven, partial, or unresolved?

v0.9 may store this additively in metadata. The stable public authority-provenance schema is deferred to v0.10.

## Non-goals

v0.9 does not add:

- new OWASP policy families;
- a large new security-rule catalogue;
- live cloud API access;
- deployment-IAM semantic expansion;
- the full effective-authority binding redesign;
- attack-path accuracy claims;
- dashboards;
- runtime MCP introspection;
- active exploitation/pentesting.

## Test requirements

Every new semantic pattern requires:

1. positive fixture;
2. negative/near-miss fixture;
3. dynamic/unresolved fixture where relevant.

LangGraph tests must prove deterministic graph nodes are not classified as agents.

Generic-loop tests must prove an LLM application without model-controlled tool dispatch is not classified as a tool loop.

MCP tests include bound, unbound, dynamic endpoint, dynamic filter, stdio, remote HTTP/SSE, ClientSession, and MCP-server-without-agent cases.

Regression fixtures should be distilled from study failure patterns rather than copying full external repositories.

## Performance

Analysis remains bounded.

Cycles in assignment, graph, registry, or helper resolution must terminate.

Target: no more than 25% median scan-time regression on the frozen cohort unless an explicitly measured recall improvement justifies an exception.

## Proposed PR sequence

1. Post-fix frozen-cohort validation harness.
2. Internal semantic-discovery primitives.
3. LangGraph v2 node semantics.
4. LangGraph v2 tools and advanced constructs.
5. Framework-neutral model/tool loops.
6. MCP discovery and binding v2.
7. Traversal hardening.
8. Integrated v0.9 frozen-180 validation.

Traversal hardening may land earlier because it is independent.

## Merge policy

Semantic changes are evaluated on:

- recall gain;
- precision loss;
- unresolved-state correctness;
- framework-specific regressions;
- effective-authority side effects;
- performance.

A recall gain does not justify silent precision collapse.

An increase in analysis-incomplete is acceptable when it replaces unsupported certainty with a correct coverage diagnostic.

## Definition of done

v0.9 is complete when:

- all scoped workstreams are merged;
- normal CI passes;
- 180/180 frozen cases complete;
- hard metric gates are met;
- no public command is broken;
- frozen study baseline/truth is untouched;
- a post-fix report documents exact v0.8 → v0.9 metric changes;
- remaining errors are classified for the next development cycle.

The target product state is a cross-framework semantic discovery engine that sees substantially more of the real agentic attack surface while remaining conservative about what static source evidence proves.
